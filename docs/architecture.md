# Архитектура StudyFlow

## Технологии

HTML5, CSS3, JavaScript (ES-модули, `type="module"`), `localStorage`, иконки Lucide. Без сборщиков, фреймворков и сервера. Запуск через Live Server.

## Модули

| Файл | Ответственность |
|---|---|
| `app.js` | Точка входа, переключение экранов, подписка на события |
| `onboarding.js` | Три слайда и экран «Готов начать?» |
| `auth.js` | Регистрация и вход |
| `home.js` | Главная и экран задач |
| `task.js` | Модель задачи: поля, статусы, приоритеты |
| `taskService.js` | Добавить, выполнить, удалить, сменить приоритет |
| `validator.js` | Проверка пользовательского ввода |
| `storage.js` | Чтение и запись `localStorage`, защита от ошибок |
| `store.js` | Общее состояние приложения |
| `progress.js` | Расчёт процента и Progress Bar |
| `filters.js` | Фильтры и сортировка |
| `ui.js` | Уведомления, общие куски разметки |
| `utils.js` | Даты, дедлайны, экранирование HTML |
| `icons.js` | Обёртка над Lucide |

## Поток данных

```
действие пользователя
        ↓
    home.js / auth.js        (события, отрисовка)
        ↓
    taskService.js           (бизнес-логика, возвращает новый список)
        ↓                ↘
    validator.js          store.js → storage.js → localStorage
        ↓
    render() → progress.js, filters.js
```

Правила зависимостей:
- `task.js`, `validator.js`, `utils.js`, `progress.js`, `filters.js` — чистые функции, без DOM и `localStorage`.
- Работа с `localStorage` только в `storage.js`.
- Работа с DOM только в экранных модулях (`home.js`, `auth.js`, `onboarding.js`) и `ui.js`.

## Объект задачи

```json
{
  "id": "t_lq3k9x2ab",
  "title": "Реферат по истории Казахстана",
  "subject": "История Казахстана",
  "deadline": "2026-11-10T18:00",
  "priority": "high",
  "status": "active",
  "createdAt": "2026-11-08T14:00:00.000Z",
  "completedAt": null
}
```

| Поле | Обязательное | Значения |
|---|:---:|---|
| `title` | да | 1–120 символов после `trim` |
| `deadline` | да | `YYYY-MM-DDTHH:mm` |
| `status` | да | `active` или `done` |
| `priority` | да | `high`, `medium`, `low` (по умолчанию `medium`) |
| `subject` | нет | любая строка |
| `id`, `createdAt`, `completedAt` | авто | служебные |

## Хранение данных

Все ключи начинаются с `studyflow:`.

| Ключ | Содержимое |
|---|---|
| `tasks` | массив задач |
| `settings` | `{ "filter": "all", "sort": "deadline" }` |
| `schedule` | массив пар |
| `cards` | массив карточек |
| `activity` | даты активности для стрика |
| `users`, `session` | локальные аккаунты |
| `onboarded` | `true`, если онбординг пройден |

Принципы:
1. При старте: нет данных, повреждённый JSON или не массив → пустой список; записи без `id`, `title`, `deadline` отбрасываются.
2. Сохранение после каждого изменения.
3. Ошибка записи → уведомление, приложение продолжает работать.

## Алгоритм прогресса

```
total   = число задач
done    = число задач со status == "done"
percent = total == 0 ? 0 : round(done / total * 100)
```

## Фильтры, сортировка, дедлайны

- Сначала фильтр, затем сортировка. Сортировка устойчивая.
  - по дедлайну, при равных датах — по приоритету
  - по приоритету, при равных — по дедлайну
  - «срочные сначала»: просроченные → ближайшие → выполненные
- Просрочена задача, если `status != done` и `deadline < сейчас`.
- Остаток времени показывается в днях, часах или минутах.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Пустое название или дедлайн | сообщение под полем, запись не создаётся |
| Некорректная дата | «Некорректная дата» |
| Повреждённый JSON | пустой список |
| `localStorage` недоступен | уведомление, работа в памяти |
| HTML или скрипт в названии | экранируется `escapeHtml()` |
